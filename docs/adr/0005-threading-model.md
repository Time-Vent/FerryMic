# ADR-0005：线程模型（逻辑职责与物理线程分离）

**状态**：已接受 Accepted

**日期**：2026-10-27

## 背景

实时音频对线程边界极其敏感。若把「逻辑职责」与「物理线程」混为一谈，会导致引擎
无法跨平台移植（不同平台的音频回调线程模型不同）。

## 决策

引擎不硬编码物理线程数量，只定义三个**逻辑执行角色**：

| 角色 | 职责 | 物理线程（第一阶段） |
|---|---|---|
| `ControlExecutor` | 命令、设备切换、参数验证、插件管理 | 应用线程 |
| `DecodeExecutor` | 文件解码、变速、预填充 SPSC 环 | 独立后台线程 |
| `RealtimeCallback` | 消费命令(≤32)、取 PCM、混音/DSP、写出 | cpal 输出回调 |

输入设备（麦克风、loopback）如有独立回调，走各自 SPSC 环 + 异步重采样汇入混音点，
不假设与输出同线程。

## 约束

- 实时回调不分配、不加锁、不做 IO、不 panic。
- 跨线程状态通过无锁原语（`Atomic*`）共享，f32 用 `AtomicU32` 位模式，不用非原子 f32。

## 后果

- 引擎可移植到任意音频后端；物理线程数量由平台适配器决定。
